# Expense Tracker v1

Expense Tracker v1 - локальное single-user приложение для личного учета денег на картах, в наличных и на криптоплатформах.

Главная идея проекта: отделить реальные расходы и доходы от технических движений денег. Перевод между своими счетами и обмен валют меняют остатки, но не раздувают статистику расходов.

## Статус проекта

Проект находится в активной разработке. API, структура данных, пользовательский флоу, визуальный стиль и стек могут меняться без сохранения обратной совместимости.

## Зачем проект

Проект полезен, когда деньги лежат в разных местах и валютах: `UAH`, `USD`, `USDT`, карта, наличные, Binance, Bybit. Обычный список трат плохо объясняет, почему изменился баланс. Здесь каждая операция хранится как движение по счетам, поэтому видно:

- сколько было на начало месяца;
- сколько пришло доходом;
- сколько ушло расходом;
- сколько перемещено переводами и обменами;
- сколько осталось на конец месяца;
- какие категории формируют расходы в каждой валюте.

## Что умеет

- Создание расходов, доходов, переводов и обменов.
- Редактирование и удаление операций.
- Несколько счетов с типами `CARD`, `CASH`, `PLATFORM`.
- Валюты `UAH`, `USD`, `USDT`.
- Архивирование счетов без потери истории.
- Управление категориями с мягким удалением.
- Сохранение исторического имени категории в операции.
- Обзор остатков и движения средств за месяц.
- Аналитика расходов по категориям отдельно для каждой валюты.
- Фильтрация журнала операций по месяцу, счетам, категориям и типу операции.

## Модель данных

Проект построен как простой ledger.

| Сущность | Смысл |
| --- | --- |
| `Account` | Счет или место хранения денег: карта, наличные, платформа. |
| `Category` | Категория расхода. Удаляется мягко, чтобы не ломать историю. |
| `Transaction` | Операция верхнего уровня: расход, доход, перевод или обмен. |
| `TransactionLeg` | Движение денег по конкретному счету: вход или выход, сумма и валюта. |

Правила операций:

- `EXPENSE` - один исходящий leg со счета и категория расхода.
- `INCOME` - один входящий leg на счет без категории.
- `TRANSFER` - два leg между своими счетами одной валюты.
- `EXCHANGE` - два leg между своими счетами разных валют, суммы указываются отдельно.

Пример: `Binance USDT -> UAH card` через P2P - это `EXCHANGE`, а не `EXPENSE`.

## История категорий

У расхода сохраняется `categorySnapshotName`. Поэтому:

- переименование категории не меняет старые операции;
- мягкое удаление категории не ломает старые расходы;
- в истории видно имя категории на момент создания операции.

## Локальный запуск

### Требования

- `Node.js >= 20.9.0`
- `npm`
- `Docker` и `Docker Compose`

### 1. Установить зависимости

```bash
npm ci
```

### 2. Создать `.env`

```bash
cp .env.example .env
```

Содержимое по умолчанию:

```env
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/expense_tracker?schema=public"
```

### 3. Поднять PostgreSQL

```bash
docker compose up -d
```

Контейнер создает локальную базу `expense_tracker` на порту `5432`.

### 4. Применить схему и базовые справочники

```bash
npm run db:push
npm run db:seed
```

`db:seed` создает стартовые счета и категории:

- `UAH card`
- `Cash UAH`
- `Cash USD`
- `Binance USDT`
- `Bybit USDT`
- `Еда`
- `Транспорт`
- `Подписки`

### 5. Запустить dev-сервер

```bash
npm run dev
```

Открой [http://localhost:3000](http://localhost:3000).

## Демо-данные

Можно заполнить проект демо-операциями за апрель и май 2026:

```bash
npm run demo:seed
```

Удалить только демо-операции и демо-категории:

```bash
npm run demo:cleanup
```

Демо-операции помечаются тегом `[DEMO_EXPENSE_TRACKER_V1]`, поэтому очистка не трогает обычные записи.

## Ограничения

- Приложение рассчитано на одного пользователя.
- Авторизации и ролей нет.
- Курсы валют не подтягиваются автоматически.
- Обмен хранит фактические суммы списания и зачисления, но не рассчитывает рыночный курс.
